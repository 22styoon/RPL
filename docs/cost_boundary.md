# 공공데이터 비용 근거의 경계

확인일: 2026-11-16. 이 문서는 현재 `src/cost_candidate.py`, `src/evidence_validation.py`, `src/public_data/contracts.py`의 동작과 비용 후보 검토 기준을 설명한다. 시설 API는 실제 인증된 JSON 정상 응답과 8페이지·786건의 수집·정규화를 확인했다. 계약 API는 JODAL 전용 키로 현황 JSON 첫 100행을 부분 수집했다. 변경·삭제 및 XML 정상 호출은 미검증이며, 검증 완료 원/t는 0건이다. 시설 명부의 정상 수집도 처리비용·처리량 근거의 검증과 별도 상태다.

## 현재 자료로 확인할 수 있는 범위

| 자료 | 직접 확인 가능한 내용 | 추가 근거 없이 확정할 수 없는 내용 |
|---|---|---|
| 생활폐기물 처리시설 API 15172490 | 업체아이디·업체명, 시설유형·시설구분, 소재지 시도·시군구 | 개별 시설의 상세주소·연간 처리용량·실제 처리량·처리원가·과거 연도 시설 명부 |
| 나라장터 계약 API 15129427 | 용역 계약번호·계약명·계약기관·계약금액·기간 문자열, 등록·변경·삭제 이력 | 계약대금의 실제 집행액, 원가 구성, 폐기물별 실적 처리량, 순수 처리 단계 단가 |
| KOSIS 폐기물 통계 | 원표 범위의 지역·연도·품목·처리방법별 관측량 | 특정 나라장터 계약 또는 시설의 처리량 분모, 해당 계약의 가격연도·포함비용 |

시설 API의 `bzentyId`는 업체아이디다. 이를 별도 시설 고유번호로 바꾸지 않는다. 시설 유형·지역이 같거나 계약명에 같은 단어가 있어도 서로 같은 처리대상이라는 증거가 되지 않는다. KOSIS의 지역 총량을 특정 계약금액으로 나누거나, 시설 개수로 계약금액을 나누어 처리단가를 만들지 않는다.

API의 연도 조회는 해당 연도의 원가 자료를 의미하지 않는다. 계약 현황은 등록일시, 변경 이력은 변경일시, 삭제 이력은 삭제일시로 조회한다. `reference_year`, `price_year`, `service_period`는 계약·처리량 원문에서 별도로 확인하며 요청연도·등록연도·공고연도에서 자동 추정하지 않는다.

## 금액·이력의 해석

| 원필드 또는 상황 | 보존·검토 원칙 |
|---|---|
| `untyCntrctNo` | 공식 통합계약 식별자. 출처와 함께 계약 이력을 묶는 기준으로 사용한다. |
| `dcsnCntrctNo`, `cntrctRefNo` | 확정계약번호와 계약참조번호를 문자열 그대로 보존한다. 여러 번호체계의 접미부에서 변경차수를 추정하지 않는다. |
| `totCntrctAmt` | 장기계속계약 전체 금액인 총부기금액이다. 일반 계약의 0과 자료 미입력을 구분한다. |
| `thtmCntrctAmt` | 금차계약금액이다. 총계약금액과 더하지 않으며, 어느 금액을 후보로 사용했는지 `amount_basis`에 남긴다. |
| 계약 현황과 변경 이력 | 같은 계약의 여러 관측·버전이다. 금액을 합산하지 않고 원문 등록·변경·삭제일시와 공개 필드의 이력을 보존한다. |
| 삭제·충돌·순서 미확인 | 삭제 이력과 서로 다른 버전을 보존한다. 대표 금액을 결측으로 두고 수동 검토 대상으로 표시한다. 삭제를 0원 계약으로 처리하지 않는다. |
| `cntrctPrd` | 날짜 하나, 날짜 범위, 착공 후 일수 등 서로 다른 표현이 가능하다. 원문을 보존하며 기간이나 연간 금액을 강제로 환산하지 않는다. |

현재 정규화 결과는 계약금액을 `public_contract_amount_not_actual_cost`, 금액 집계를 `not_summed`으로 표시한다. 계약명 분류는 수집 대상 탐색을 돕는 문자열 분류이며 원가·업무범위 검증이 아니다. 운영·유지관리, 수집·운반, 처리 용역, 시설 공사, 장비 구매, 설계·감리, 혼합 범위와 미분류를 구분하고 필요한 수동 검토 상태를 보존한다. 분류가 하나로 정해져도 계약서·과업지시서의 범위 대조는 필요하다.

## 단가 후보의 필수 대조

금액을 처리량으로 나누기 전에 다음 항목을 계약 근거와 처리량 근거 양쪽에서 확인한다. 현재 후보 생성기는 `contract_evidence`와 `throughput_evidence`를 함께 보존해 이 대조를 재현한다.

| 대조 항목 | 필요한 확인 |
|---|---|
| 출처 | 양쪽의 `source_id`, 공개 HTTP(S) `source_url`, 계약 식별자 |
| 기간·연도 | 동일한 `service_period`, 명시적인 `reference_year`; 금액의 `price_year`와 가격 기준 |
| 지역 | 동일한 `geography`; 계약기관 소재지와 실제 서비스 지역의 구분 |
| 대상 폐기물 | 동일한 `scope`, `material_type`; 생활폐기물·사업장폐기물 및 품목 범위 |
| 처리 단계 | 동일한 `process_stage`; 수거·운반·선별·재처리·잔재 처분 등의 경계 |
| 금액 | 0 이상인 유한한 `amount_krw`, 총액·금차액 등 `amount_basis`, 부가세·정산 범위 |
| 처리량 | 0보다 큰 유한한 `throughput_t`, 실적·계약물량 등 `throughput_basis`; 톤 단위 확인 |
| 포함항목 | 인건비·운송·처분·자본·이전지출의 포함 여부를 각각 명시적인 참/거짓으로 확인 |
| 중복 | `overlap_risk=False`, 동일 계약·기간·범위의 중복 후보와 중복 계상 해소 |

미확인은 `None` 또는 빈 칸으로 남긴다. 미확인을 0원·0톤·`False`로 대체하지 않는다. 유효한 명시적 0원과 미입력은 다르며 0톤은 단가 분모로 허용하지 않는다. 자료형이 잘못되거나 수치가 유한하지 않으면 오류로 처리한다.

계약금액과 처리량이 같은 연도라는 사실만으로 기간·지역·품목·단계가 일치하지는 않는다. 금액이 여러 업무를 묶고 있으면 근거 있는 분리내역이 필요하다. 계약명이나 금액 비율로 특정 단계의 비용을 임의 배분하지 않는다. 예산·낙찰·계약·집행·정산 금액의 차이는 금액 기준에 남기며 동일한 원가 관측값으로 취급하지 않는다.

## 비용에 포함할 항목과 중복 경계

| 항목 | 모형에 적용하기 전 확인할 경계 |
|---|---|
| 수거·운반 | 처리 계약에도 운송비가 포함돼 있는지 확인해 같은 물량의 운송비를 두 번 넣지 않는다. |
| 선별·재처리·처분 | 처리 단계와 잔재 처리 포함 여부를 확인한다. 기존 처리 단가가 잔재의 외부 처분비를 포함하면 별도 잔재 단가와 중복될 수 있다. |
| 인건비·관리비 | 운영 계약 총액에 이미 포함된 인건비·관리비를 별도 항목으로 다시 더하지 않는다. |
| 시설 공사·장비·자본 | 일회성 자본계약을 연간 운영비로 쓰지 않는다. 자본의 포함 여부와 추가 투자 연간화의 중복을 확인한다. 할인율·수명·추가 투자 범위는 별도 근거 또는 명시적 가정이다. |
| EPR 분담금·세금·보조금 등 | 이전지출은 사회적 실물비용 단가에 더하지 않는다. 현 검증기는 `includes_transfer=True` 후보를 배제한다. |
| 생산자 실물비용 | 분담금과 구분하고, 생산 공정 변경에 따른 추가 자원 비용에 대한 별도 근거가 필요하다. |
| 가계 시간 | 가구 수·실측 시간·시간가치가 별도로 필요하다. 공공 계약금액에서 가계 시간비용을 추정하지 않는다. |
| 판매수입·환경편익 | 비용 관측과 별도 경계를 갖는다. 재활용품 판매수입이나 미계측 환경편익을 계약 총액에서 자동 차감하지 않는다. |

이 자료만으로 총사회적 비용·순후생을 산정하지 않는다. 현재 정책 실험의 범위 내 비교비용과 구로구 예산 대리값의 경계는 [방법론](methodology.md)과 [가정](assumptions.md)을 따른다. 새 공공 API 수집은 기존 지역별 미입력 단가를 채우거나 구로구 예산을 다른 지역으로 자동 외삽하는 기능을 제공하지 않는다.

## 후보 상태와 검토

| 상태 | 조건과 허용되는 결과 |
|---|---|
| `candidate` | 원자료 또는 범위·포함항목·처리량 대조가 미완료. `computed_krw_per_t=None`을 유지한다. |
| `proxy` | 금액과 처리량의 필수 근거·범위·포함항목이 확인되고 일치하며 이전지출·중복 위험이 없어 검증을 통과한 대리값. 그때만 금액/톤을 계산한다. 현재 코드의 후보 증거등급은 C다. |
| `validated` | 검증을 통과한 후보에 대해 `validated`를 명시적으로 요청하고 외부 검토를 남긴 상태. 현재 코드는 `reviewed_by` 또는 `review_note`와 `explicit_approval=True` 조합을 요구하며 후보 증거등급은 B다. |
| `rejected` | 범위·기간 불일치, 다른 계약의 처리량, 이전지출 포함, 중복 위험·중복 후보 또는 명시적 배제. 단가를 부여하지 않고 사유를 남긴다. |

상태 흐름은 `candidate → proxy → validated`이며 문제가 확인되면 `rejected`로 보존한다. 필요한 근거가 없는 후보는 계산하거나 승격하지 않는다. API 제공기관이 공식이라는 사실은 적용 단가의 검증등급을 자동으로 높이지 않는다. 합성 테스트 데이터의 상태 전이는 실제 원가가 검증됐다는 증거가 아니다.

일반 CSV의 후보 열 외에도 두 근거 객체, 서비스 기간, 검토자·검토 의견·승인 표시를 함께 보존해야 검증을 재현할 수 있다. 같은 계약에 금차액·총액을 각각 후보로 만들 수 있어도 동시에 합산하지 않으며, 후보 집합의 계약·기간·범위 중복을 검토한다.

**어느 상태도 모형 입력 자동 반영 권한을 부여하지 않는다.** 수집 CLI와 후보 생성기는 기존 정책 설정·단가를 수정하지 않는다. 원/톤 입력 적용은 근거와 범위를 검토한 뒤 별도 명시적 변경으로 수행한다. 현재 실제 처리량과 포함항목이 확인되지 않은 API 수집 결과에서는 원/톤을 산출하지 않는다.

## 공개 근거와 보존

공식 API와 명세의 확인 범위는 [공공데이터 API 목록](public_data_api_inventory.md)에 정리한다. [시설 공식 페이지](https://www.data.go.kr/data/15172490/openapi.do), [계약 공식 페이지](https://www.data.go.kr/data/15129427/openapi.do), [계약 참고문서 2026-11-10판](https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=FILE_000000007761074&fileDetailSn=1)을 근거로 사용했다.

수집 보존본은 공개 필드 허용목록을 적용한 redacted snapshot이다. API키와 담당자명·전화·팩스 및 개인·연락처를 포함할 수 있는 `corpList`, `dminsttList` 같은 묶음 문자열은 보존하지 않는다. 비용 후보의 추가 근거도 공개 출처와 필요한 금액·물량·범위 중심으로 기록한다. 공식 응답 원문에 있던 필드가 보존본에서 제외됐으면 제외 목록과 허용된 메타데이터로 그 사실을 확인한다.
