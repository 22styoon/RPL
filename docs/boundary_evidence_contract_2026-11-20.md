# 월별 코드·명칭 감사의 입력·증빙 연결 규약

작성일: 2026-11-20 (Asia/Seoul)

이 규약은 과거에 성공한 행정코드·명칭 감사를 **현재 분석 입력에도 적용할 수 있는지** 확인한다. 감사 완료 문구만 복사하지 않고, 실제로 확인한 로스터와 원문 증빙의 연결을 재검증한다. GIS 경계 도형, 정책 적용권역, 실제 정책 시행 및 인과효과는 별도 검증 대상이다.

## 1. 무엇을 입력 지문으로 기록하는가

폐기물 통계 로스터는 `sigungu_code`, `sido_name`, `sigungu_name`의 조합을 사용한다. 재질별 반복 행을 제거하고 일정한 순서로 정렬해 SHA-256을 계산한다. 월별 MOIS 로스터에는 `reference_month`를 더한다. 필수값 누락이나 같은 코드에 모순되는 명칭이 있으면 정상 로스터로 인정하지 않는다.

따라서 행 순서·재질별 반복 횟수·발생량·처리량·인구·세대수·기존 적합성 표시가 바뀌어도 **논리적 지리 로스터가 같으면** 지리 입력 지문은 유지된다. 이 성질은 처리량이나 인구가 정확하다는 보장이 아니다. 물질수지·통계 출처·정책 노출의 검증은 별도로 수행한다.

감사 manifest는 버전이 있는 입력 연결 정보와 함께 다음을 확인한다.

- 감사한 폐기물 통계단위 로스터와 현재 로스터가 일치한다.
- 감사한 월별 로스터와 현재 저장된 월별 CSV가 일치한다.
- API 원문 페이지의 파일 해시와 요청조건이 감사 기록과 일치한다.
- 현재 12월 행정코드 CSV와 MOIS 수집 checkpoint가 있으면, 그 로스터도 감사의 12월 자료와 일치한다.
- 증빙 파일 경로가 작업 폴더 안에 있고 필요한 파일이 존재한다.

논리적 로스터 지문과 원문 파일 해시는 서로 다른 검증이다. 인구만 달라져 논리적 지문이 같더라도 저장된 원문 페이지의 바이트가 감사 때와 달라지면 원문 증빙 검사는 통과하지 않는다. 해시는 파일·입력의 동일성을 확인하며 원문 통계의 정확성이나 API 응답의 진실성을 증명하지 않는다.

## 2. 언제 기존 완료 표시를 사용할 수 없는가

입력 연결 정보가 없는 과거 감사는 당시의 성공 기록으로 보존하되 현재 검증으로 인정하지 않는다. 현재 로스터 변경, 원문 페이지 변경·누락, 요청조건 불일치, 검토가 필요한 감사 결과도 같은 방식으로 처리한다. 이유를 상태 코드로 남기고, 완료 상태를 추정해 복구하지 않는다.

`scripts/audit_regional_boundaries.py --check-only`는 네트워크 호출이나 자료 재작성을 하지 않는 로컬 확인 명령이다. 현재 입력·증빙 연결을 검증하면 종료코드 `0`, 검증하지 못하면 종료코드 `2`를 반환한다. 키가 설정돼 있다는 사실이나 과거 보고서의 완료 표시는 이 검증을 대신하지 않는다.

일반 감사 명령도 `current_input_assessment`를 함께 출력한다. 월별 감사가 `complete`이고 현재 입력·증빙 검증도 성공해야 종료코드 `0`을 반환한다. 월별 목록 자체의 일치와 현재 사용 중인 자료에 그 결과를 적용할 수 있는지는 각각 확인한다.

## 3. 정책 원문 검증과 결과 결합은 분리한다

정책 문서의 근거 검증 건수와 현재 입력으로 인정되는 정책·성과 결합 건수는 다른 값이다. 지리 근거를 재검증해야 하더라도 정책 문서 자체의 근거가 자동으로 사라지는 것은 아니다.

반대로 현재 지리 감사가 유효해졌다는 이유만으로 과거 결합을 다시 인정하지 않는다. 저장된 결합에는 별도의 `policy_join_boundary_input_verified` 표시와 현재 감사에 대응하는 폐기물·월별 로스터 지문이 필요하다. 이 연결이 확인되지 않으면 결합을 재생성해야 한다. 과거 건수는 `cached_verified_join_rows`에 남길 수 있지만 현재 검증 건수와 구분하며, 보고서나 화면에서 반복 처리해도 과거 건수가 자동으로 되살아나지 않는다.

앱은 메뉴를 열 때 현재 입력을 다시 확인한다. 현재 근거가 확인되지 않는 저장 보고서는 과거 생성 결과로 표시한다. 정적인 HTML·CSV 자체가 나중의 입력 변경에 따라 자동 수정되는 것은 아니므로, 입력 변경 뒤에는 감사·결합·보고서를 순서대로 갱신한다.

## 4. 재현 순서

공식 원문과 12월 MOIS 자료를 수집한 뒤 기본 지역 표를 준비한다. 처음에는 월별 감사 전 상태일 수 있다.

```powershell
.\.venv\Scripts\python scripts/prepare_regional_recycling.py --year 2024
.\.venv\Scripts\python scripts/audit_regional_boundaries.py
.\.venv\Scripts\python scripts/audit_regional_boundaries.py --check-only
.\.venv\Scripts\python scripts/join_regional_policy.py --year 2024
.\.venv\Scripts\python run_statistical_analysis.py
```

감사 실행은 저장된 월별 API 페이지를 재사용할 수 있다. 공식 원문을 다시 받아야 할 때는 `audit_regional_boundaries.py --refresh`를 사용한다. `join_regional_policy.py`는 지역 입력을 다시 준비하고 정책의 연도·기간·재질·범위·실제 시행 근거를 재검증한다. 조례 제목·본문 또는 코드 일치만으로 실제 운영정책을 확정하지 않는다.

## 5. 2026-11-20 실자료 재현 결과

[전국 폐기물 발생 및 처리현황 공식 상세자료](https://kwaste.or.kr/data/01.php)의 2024년 원표와 [행정안전부 주민등록 인구통계 API](https://www.data.go.kr/data/15108065/openapi.do)를 이용했다. 원표를 읽는 데 필요한 `openpyxl`을 실행 의존성에 추가했다. 원문과 지역별 상세 행은 재배포 조건을 확인하기 전까지 로컬에 두며 Git 추적에서 제외한다.

실자료의 `--check-only` 결과는 `verified=true`, `status=code_name_roster_stable`이었다. 지역 자료를 다시 준비하고 시도·시군구 보고서도 재생성했다. 실제 정책 시행 근거를 갖춘 정책·성과 결합은 **0행**이다. 이 결과는 통계에 사용한 코드·명칭 목록의 일관성에 한정되며, GIS 도형이나 정책 효과를 확인한 결과가 아니다.

최종 검증에서 `python -m pytest -q`는 **587개 통과, 건너뜀 0개**였다. 원표가 없어 건너뛰던 시군구 실자료 검증도 이번에는 실행했다. 종합 분석·지표 보고서 생성과 Python 컴파일도 완료했다. 입력 교체·원문 변경·12월 자료 불일치·과거 결합 수치 재사용을 막는 회귀 검증에는 가상 자료를 사용하며, 이를 추가 관측값으로 세지 않는다.
